### 1.1 O escopo estava errado, e o modo de falha era o pior possível

Medido um a um contra o servidor de autorização:

```
cobranca_boletos_incluir     HTTP 400  invalid_scope     <- a familia que o codigo pedia
cobranca_boletos_consultar   HTTP 400  invalid_scope
cobranca_boletos_baixa       HTTP 400  invalid_scope
cobranca_boletos_pix         HTTP 400  invalid_scope
boletos_inclusao             HTTP 200  CONCEDIDO
boletos_consulta             HTTP 200  CONCEDIDO
boletos_alteracao            HTTP 200  CONCEDIDO
webhooks_inclusao/consulta/alteracao   HTTP 200  CONCEDIDO
```

**O código do erro é o que importa: `400` na requisição do TOKEN, e não `403` na
emissão.** O token não nasce — e a mensagem que `http.ts` imprime nesse caso manda
*"conferir se o aplicativo está AUTORIZADO no portal"*. O primeiro boleto teria
falhado apontando para o banco, com a causa dentro de casa.

**E a lição não é "o realm mentiu".** O `scopes_supported` lista os 29 de verdade —
o realm é compartilhado por todos os cooperados e anuncia o catálogo inteiro.
**Anunciar não é conceder**, e nenhuma leitura de `openid-configuration`
distinguiria as duas coisas.

`ESCOPOS` passou a ter **três** e não os seis concedidos, pelo princípio que já
estava escrito ali. Os de webhook ficam de fora até existir quem os use — e a
`Q-WEBHOOK-CADASTRO-01` perdeu o impedimento de permissão.

### 1.2 A migration 36 entrou, e a leitura que mentia foi vista dos dois lados

Aplicada pelo `migrate-financeiro` com `conferencia = migration-36`. Da conexão de
dono o `migrate status` listou **1** pendente. Daqui da VPS ele dizia **36**, todas
— a leitura que mente por RLS sem policy em `_prisma_migrations`. Agora está
medido dos dois lados.

**O modo `migration-36` do `conferir-banco-alvo.ts` nasceu nesta leva**, e tem uma

## 6. Armadilhas medidas que voltam a morder

- **`git push` daqui é bloqueado pelo classificador** — entregar o comando ao dono,
  como no banco e no nginx;
- **⚠️ OWNERSHIP: commit daqui derruba o deploy.** O deploy roda `git` e o build como
  usuário **`financeiro`**, e as sessões commitam como **root**. O build morre em
  `EACCES … unlink web/dist/assets/…`. Depois de commitar:
  `chown -R financeiro:financeiro /opt/financeiro/app`, e conferir
  `find /opt/financeiro/app -user root | wc -l` = **0**. O `git status`/`fetch` como
  `financeiro` **passa** mesmo com arquivos de root — a falha só aparece três passos
  adiante, no build;
- **Produção pode estar em deriva do próprio disco:** o serviço roda de
  `/opt/financeiro/app`, que é o repo onde se commita. Conferir
  `systemctl show financeiro.service -p ActiveEnterTimestamp` contra o `git log`;
- **PostgREST trunca em 1000 linhas** com `limit` maior — paginar. Custou uma
  conclusão errada sobre datas de funil antes de eu conferir a contagem;
- **`claude-sonnet-5` não aceita prefill de mensagem `assistant`** — devolve `400`;
- **o `isolamento` não dispara para mudanças em `scripts/`** — o filtro de `paths`
  não inclui esse diretório, e o `conferir-banco-alvo.ts` mora lá;
- o node do PATH é antigo (`export PATH=/opt/financeiro/node/bin:$PATH`) · não há
  `.env` na aplicação, use `systemd-run --property=EnvironmentFile=/etc/financeiro.env`
  · o sandbox da Sicoob é mock estático · as páginas do portal são SPA.
